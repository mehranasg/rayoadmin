# وضعیت فعلی (۱۴۰۵/۰۸/۱۹)

## خلاصه
- **اپ:** `app/` پنل مدیریت کافه‌رستوران رایو است: یک صفحهٔ ایستای HTML/CSS/JavaScript، بدون build و فریم‌ورک.
- **داده:** مستقیم به API ‏RayoData وصل است (`https://chat.yekzan.com/api/v1.0/RayoData/`) و روی **دادهٔ زندهٔ رایو** می‌خواند و ثبت می‌کند.
- **ورود:** یک صفحهٔ ورود مشترک دارد.
- **بخش‌ها:** هفت بخش اصلی (میز کار، مالی، انبار، پرسنل، منو و قیمت، گزارش‌ها، تنظیمات)، به‌علاوهٔ «مشتریان» (نمونه) و «طرح جامع» (فقط مالک).
- **کنار گذاشتن پنل قدیمی:** همهٔ امکانات پنل قدیمی (`legacy/`) منتقل شده‌اند، جز آنچه در بخش «وابستگی به پنل قدیمی» آمده است.
- **داده‌ها:** شکل رکوردها همان شکل پنل قدیمی است، پس هر دو پنل روی یک داده کار می‌کنند. هیچ migration یا تغییر بک‌اندی لازم نشده است.

قواعد محاسبهٔ هر بخش: [reference/BUSINESS_RULES.md](reference/BUSINESS_RULES.md) · ساختار کد: [ARCHITECTURE.md](ARCHITECTURE.md) · مدل داده: [reference/DATA_MODEL_V10.md](reference/DATA_MODEL_V10.md)

## ورود، کاربران و دسترسی
- **مالک:** سه کاربر ثابت (Admin، Ziba، Mehran) با دسترسی کامل.
- **کاربران پنل:** در `personnel.settings.adminUsers` ذخیره می‌شوند و دسترسی‌شان به تفکیک بخش است. کلیدهای دسترسی: `cash`، `inventory`، `inventoryEdit`، `purchase`، `financeLedger`، `assets`، `personnel`، `payroll`، `shift`، `menu`، `pricing`، `reports`، `sales`، `settings`. تعریف و ویرایش کاربر در «پرسنل ← کاربران و دسترسی» است.
- **دیدن از دید نقش‌ها (مالک):** مدیر میانی، حسابدار، انباردار، صندوقدار، یا هر کاربر واقعی. ثبت‌ها به نام مالک می‌مانند.
- **محدودیت امنیتی:** کنترل دسترسی فقط در مرورگر است و API خودش دسترسی را بررسی نمی‌کند (BL-003). رمز پرسنل در پنل پرسنل هنوز هش نیست (BL-002).

## بخش‌ها

### میز کار (`#/home`)
- **کارهای روزانه:** گزارش صندوق، فروش روز، شمارش نوشیدنی، انعام، فاکتور خرید، ورود به انبار، پرتی و مصرف پرسنلی، پرداخت به پرسنل و تأمین‌کننده، جریمه و تخلف. برای هر کار، وضعیت دیروز و امروز و دکمهٔ ثبت دارد. کار ضروریِ ثبت‌نشدهٔ دیروز قرمز می‌شود.
- **«آنچه باید دید»:** هشدارها از روی داده، مثلاً فروش واردنشده، گزارش صندوق بررسی‌نشده، موجودی منفی، آیتم بدون رسپی.
- **«ثبت جدید»:** منوی ثبت سریع بالای همهٔ صفحه‌ها. اولین گزینه‌اش «آخرین قیمت خرید» است.

### انبار (`#/inventory`) — تک‌انباره
| تب | امکانات |
|---|---|
| داشبورد کنترل | گزارش دوره، گردش مواد، «کجا دنبال مغایرت بگردم»، پرتی، نوشیدنی (با فهرست روزانهٔ ثبت‌ها و مغایرت شبانه)، انبارگردانی‌ها، ورود، فروش، خروجی AI |
| موجودی | موجودی امروز هر قلم (آخرین شمارش + ورود − مصرف رسپی − پرتی)، ارزش، منفی‌ها، نیازمند سفارش |
| ورود کالا | ورود چندردیفه به واحد انبار یا خرید؛ ویرایش و حذف (ابطال) |
| فروش | ورود فایل «تعداد فروش کالا» سپیدز یا اسنپ، تطبیق آیتم، سوابق، ابطال |
| ضایعات | پرتی و مصرف مجاز (ماده، آیتم منو طبق رسپی، یا قلم آماده طبق فرمول)، «ذخیره و ثبت بعدی»، تعویض روغن، ویرایش و حذف |
| شمارش | شمارش کور پایان روز (مستقیم + اقلام آماده)، شمارش با تاریخ گذشته، بازمحاسبهٔ خودکار مغایرت شمارش‌های بعدی، حذف شمارش یک روز، «گزارش شمارش‌ها» (یک شمارش و روند مغایرت در بازه، واحد زیر مقدار شمرده‌شده)؛ برای دارندهٔ دسترسی ویرایش انبار: ویرایش یا حذف یک قلم شمرده‌شده، «ویرایش کل این شمارش» (فرم شمارش با مقادیر ثبت‌شدهٔ همان روز؛ فقط مقادیر تغییرکرده ذخیره می‌شوند)، ابطال کل شمارش؛ در فرم شمارش واحد و معادل واحد پایه زیر هر مقدار |
| شمارش نوشیدنی | جدول روزانهٔ یخچال‌ها (صبح، ورودی، فروش، شب)، روزهای گذشته هم ثبت می‌شوند |
| سفارش | نقطهٔ سفارش و موجودی هدف |
| درخواست خرید | درخواست پرسنل، تأیید، سفارش، بستن با دریافت |
| مصرف | وضعیت مصرف اقلام با مرز هشدار، اثر اتلاف روی آیتم‌های منو، سهم روغن سرخ‌کن هر آیتم و ثبت آن در رسپی |
| تنظیمات | سرخ‌کن‌ها، اقلام سر میز، سطح کنترل (سبک/دقیق/کنارگذاشته)، نقطهٔ سفارش، نوشیدنی‌های کنترل روزانه، صفرگذاری اقلام شمارش‌نشده با بازگردانی، هشدارهای مدیریت مصرف |
| کالاها و مواد | کاتالوگ اصلی (`pricing.ingredients`)، اقلام آماده‌سازی (فرمول و نسخه)، «آخرین قیمت‌ها» (دستی یا از Excel، با فایل خالی و نمونه)؛ ستون آخرین شمارش؛ فیلتر هرگز شمارش‌نشده، شمارش قدیمی، بدون استفاده، بدون قیمت، آرشیو؛ «پاک‌سازی» و «حذف قلم» در فرم قلم برای مدیر اصلی (حذف قلم بی‌سابقه یا فقط با شمارش صفر، آرشیو قلم دارای سابقه)؛ فرم قلم پهن و سه‌ستونه |

### گزارش‌ها (`#/reports`)
نمای مدیریتی (آخرین ماه کامل، بیشترین خرید، حساب‌ها)، ماه به ماه، تحلیل فروش (دسته‌ها و پرفروش‌ها از فایل فروش).

### تنظیمات (`#/settings`)
- **عمومی، «تنظیمات پایه»:**
  - نام مجموعه و فهرست‌های پرسنل؛
  - قاعدهٔ مرخصی و نمایش جریمه برای پرسنل؛
  - محل‌های پرداخت و جهت تسویه؛
  - فهرست‌های مرجع تأمین‌کنندگان؛
  - واحد نمایش مبالغ؛
  - الزام کد سپیدز.
- **داده و بکاپ:**
  - وضعیت ماژول‌ها؛
  - بکاپ کامل ZIP؛
  - **بازگرداندن بکاپ** (فقط مالک، با پیش‌نمایش، پشتیبان پیش از نوشتن، عبارت تأیید و بازگشت خودکار در خطا).
- **تاریخچهٔ تغییرات** و **لاگ خطاها.**

## نرم‌افزارهای داخل مجموعه (فقط دمو)
`app/pos.html` (صندوق)، `waiter.html` (سفارش‌گیر)، `kds.html` (آشپزخانه)، `staff.html` (پنل پرسنل). روی دادهٔ نمونهٔ `js/ops-data.js` کار می‌کنند و فقط مالک لینکشان را در منو می‌بیند.

## داده و API
- **ماژول‌های داده:** `personnel`، `suppliers`، `pricing`، `inventory`، `cashreport`، `assets`، `finance`، `attendance`، `survey`، `errorlog`، `sepidsaudit`. هر ماژول یک سند JSON است.
- **API:** دو عمل اصلی `Load?module=` و `Save?module=`، به‌علاوهٔ `Query` و `Mutate` برای رکوردهای صندوق و مالی.
- **واحد پول:** گزارش صندوق به ریال ذخیره می‌شود؛ بقیه به تومان. نمایش تومان یا ریال است.
- **تقویم:** تاریخ‌ها شمسی و به شکل `۱۴۰۵/۰۸/۱۹`.

## وابستگی به پنل قدیمی (`legacy/`)
پنل قدیمی منجمد است و دوباره منتشر نمی‌شود، ولی این‌ها هنوز فقط در آن هستند:
- **صفحه‌های پرسنل و صندوق‌دار** (`legacy/personel/*`، `staff-panel.html`، فرم گزارش صندوق صندوق‌دار): هر روز استفاده می‌شوند (BL-001).
- **آموزش و چک‌لیست**، **آنالیز فروش** و **فرم نظرسنجی**: کنار گذاشته شده‌اند (BL-007 تا BL-009).
- **ابزارهای راه‌اندازی:** شروع دوباره از تاریخ، بازنشانی شمارش‌ها، بازنشانی جداول، بارگذاری اولیه (BL-011).
- **محدودیت زیر-رسپی:** پنل قدیمی سطر «قلم آماده» در رسپی را نمی‌شناسد. رسپی‌هایی که این سطر را دارند فقط در اپ جدید ویرایش شوند.

## بخش‌های نمونه
وقتی دادهٔ زنده وصل است، تب‌هایی که فقط طرح‌اند پنهان می‌شوند:
- **مالی:** AI، بستن ماه، گزارش؛

- **گزارش‌ها:** کتابخانه، AI، ممیزی؛
- **منو:** کانال‌ها؛
- **تنظیمات:** فهرست، اتصال‌ها.

بخش «مشتریان» (رزرو و نظرسنجی) هنوز دادهٔ نمونه است (BL-013).
