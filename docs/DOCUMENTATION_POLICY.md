## اختلاف منابع

برای واقعیت پیاده‌سازی: **سورس/تست جاری، سپس آخرین درخواست صریح کاربر، سپس مراجع جدید، سپس تاریخچه**. درخواست کاربر مبنای رفتار مطلوب و مجوز کار است؛ تست یا سورس ممکن است هنوز آن را محقق نکرده باشد. اختلاف را ثبت کنید و برای همسان‌کردن مستندات، برنامه را بی‌درخواست تغییر ندهید.

وضعیت هر قابلیت یکی از `Implemented`، `Partial`، `Planned`، `Deprecated` یا `Unverified` باشد. `Implemented` اثبات استقرار یا صحت دادهٔ زنده نیست؛ شواهد، دامنهٔ آزمون و محدودیت Backend را جدا بنویسید. نتیجهٔ QA قدیمی را به زمان جدید نسبت ندهید.

چهار سند تفصیلی باقی‌ماندهٔ تاریخی، الزامات فعلی نیستند: Handoffهای v10.5.0، v10.8.0، v10.8.1 و طرح SQL v10.8.0. هشدار ابتدای آن‌ها بر تمام متن بعدی، از جمله «این سند را اول بخوانید»، «۱۲ تب»، Reset از Seed و API دو action، حاکم است. [مدل JSON تاریخی](../RAYO_DATA_MODEL_v10_8_0.json) نیز schema رسمی یا DTO جاری نیست. خواندن خودکار این فایل‌ها و آرشیوهای Seed ممنوع است.

## چرخهٔ تغییر

1. قبل از توسعه فقط سند مرتبط، HTML/CSS، تمام patchهای بارشده و تست همان حوزه را بخوانید.
2. تغییر رفتار و قرارداد را در همان PR/commit ثبت کنید؛ وضعیت `Planned` فقط پس از وجود کد و شواهد به `Implemented` تبدیل شود.
3. تصمیم مهم با دلیل، اثر JSON/Backend و rollback در بخش تصمیم‌های راهنمای مهاجرت ثبت شود. برای هر اصلاح فایل نسخه‌ای تازه نسازید.
4. تغییر صرفاً متنی: لینک‌ها، نمونه‌های JSON، اختلاف Git و نبود وابستگی Runtime بررسی شود. تغییر JavaScript: syntax، QA مرتبط، تست دستی صفحه و کنترل عدم Seed/Save در Load الزامی است.
5. پایان کار: فایل‌های تغییرکرده، نتایج واقعی آزمون، آزمون اجرا‌نشده و اثر داده/Backend گزارش شود. تاریخچه در Git است؛ ZIP کامل فقط milestone/استقرار یا درخواست صریح.

## حذف یا آرشیو

قبل از حذف، فهرست با دلیل و مقصد انتقال اطلاعات تهیه، از اصل فایل‌ها خارج از مخزن Backup زمان‌دار با manifest و SHA-256 گرفته و محتویاتش آزموده شود. ارجاع اجرایی/تست/مستند و تغییرات ثبت‌نشده بررسی شوند. قراردادها، migrationها، تست‌ها، Seed، assets و داده صرفاً به‌دلیل نام نسخه‌ای حذف نمی‌شوند. در ابهام فایل نگه داشته و دلیل ثبت شود.

اطلاعات معتبر منحصربه‌فرد ابتدا به مرجع تخصصی منتقل و لینک‌های فعال اصلاح شوند. سند فعلی تا کامل‌شدن و اعتبارسنجی جایگزین باقی بماند. آرشیو خارج از مخزن خوانده نمی‌شود مگر برای بازیابی مشخص؛ در Git هیچ Backup زنده، رمز، token، کلید، حساب بانکی یا payload شخصی ثبت نشود.

نمونه‌ها ساختگی و مشخصاً برچسب‌دار باشند. مسیر endpoint/فیلد فعلی باید شاهد سورس داشته باشد؛ endpoint پیشنهادی فقط در راهنمای آینده و با برچسب `Planned` نوشته شود. نرخ‌های مالی برنامه پارامتر نرم‌افزارند و نباید مقررات مالیاتی جاری معرفی شوند.
