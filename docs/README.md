## قواعد مستندسازی
1. **یک واقعیت، یک جا.** هر موضوع سند مالک خودش را دارد (جدول بالا) و بقیه به آن لینک می‌دهند. متن تکراری ننویسید.
2. **اسناد وضعیت فعلی را می‌گویند، نه تاریخچه را.** تاریخچه در git و در `DECISIONS.md` است. گزارش کار، یادداشت تحویل و نسخهٔ تاریخ‌دار سند (`_v10_12.md`) نسازید.
3. **همراه کد.** تغییر کد و تغییر سند مالکش در **یک کامیت** می‌روند.
4. **شناسه‌ها پایدارند.** بندهای `BL-###` (بک‌لاگ) و `R#.#` (طرح توسعه) هیچ‌وقت شماره‌گذاری دوباره نمی‌شوند. بند انجام‌شده یا کنارگذاشته با وضعیتش می‌ماند.
5. **نیاز عمومی جدا از نیاز رایو.** هدف، محصول قابل فروش به کافه‌رستوران‌های دیگر است. اگر قاعده‌ای فقط برای رایو است (مثلاً سپیدز، ساعت باز بودن، فهرست سرخ‌کن‌ها)، همین را صریح بنویسید تا در محصول به «تنظیم» تبدیل شود.
6. زبان اسناد فارسی است. نام فایل، کلید داده و کد به همان شکل کد می‌آیند.
