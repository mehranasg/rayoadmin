# صفحهٔ تنظیمات، تنظیمات نرم‌افزار و بازنشانی جداول

> ضمیمهٔ تخصصی `settings.html`. مالک‌ها: 16 (route)، 44 (منو و تب‌های بالا)، 48 (هاب تنظیمات نرم‌افزار)، 38 (Backup)، 39 (Initialize/Reset/Restore)، 17/19/37 (کارت‌های تنظیمات پنل).

## ۱. ناوبری

- منوی سمت راست «تنظیمات» به `settings.html` می‌رود و نمای پیش‌فرض آن `softwareSettings` است (16 و 44).
- تب‌های بالای صفحه (`SUB.settings` در 44): «تنظیمات نرم‌افزار»، «اطلاعات پایه و مدیریت اقلام» (`base-data.html`)، «مدیریت اطلاعات و بکاپ» (`view=dataManagement`)، «تنظیمات پنل و امکانات» (`view=settings`)، «تنظیمات تخلفات»، «تغییرات»، «لاگ خطاها».
- لینک‌های قدیمی `personnel.html?view=...` برای این نماها به `settings.html` هدایت می‌شوند؛ Back/Forward مسیر را حفظ می‌کند.
- تب «تنظیمات» صفحهٔ قیمت‌گذاری مستقیماً به `settings.html?view=softwareSettings&section=pricing` می‌رود و `pricing.html?tab=settings` به همان‌جا هدایت می‌شود.

## ۲. هاب «تنظیمات نرم‌افزار» (48)

بخش با منوی کشویی و پارامتر `section` در URL انتخاب می‌شود. هر بخش کارت‌های **همان فرم و همان دکمهٔ ذخیرهٔ ماژول مالک** را نشان می‌دهد؛ منبع دادهٔ جدید یا نسخهٔ دوم تنظیمات وجود ندارد. هر بخش ماژول خودش را فقط Load می‌کند؛ خطای Load کارت خطا و «تلاش دوباره» دارد. تغییر ذخیره‌نشده هنگام رفتن به بخش دیگر پرسیده می‌شود.

| section | محتوا (منبع/مالک) |
|---|---|
| `general` | نام رستوران/برند (کارت `views.settings`)، نمایش امکانات پنل (`RayoPhase1.featureSettingsCard`، 44)، نمایش اطلاعات در پنل پرسنل (`RayoV104.staffVisibilityCard`، 37) — سند HR |
| `personnel` | فهرست‌های قابل انتخاب و نقشهٔ سکشن‌ها (کارت‌های `views.settings`) — HR |
| `payroll` | پارامترهای محاسباتی، تنظیمات پایهٔ مدل حقوق (`views.salarySettings`)، مرخصی، تقویم تعطیلات، حساب‌ها و محل‌های پرداخت حقوق (کارت‌ها و حساب‌های صندوق `crDestinations` از 11 + محل‌های پرداخت `paymentOptionsSettingsSection` از 19) |
| `pricing` | گام گردکردن و سقف بهای تمام‌شدهٔ دسته‌ها (`RayoMenuV1011.pricingSettings`، 45) — pricing |
| `inventory` | تنظیمات پیش‌بینی اقلام عملیاتی (`RayoInventoryV1012.forecastSettingsPanel`، 46) — inventory |
| `purchase` | محل‌های وجه (19) و فهرست‌های مرجع تأمین‌کنندگان (`supplierJsonSettings`، 04) |
| `finance` | تنظیمات مالی و پیش‌فرض محاسبه‌گر (`finSettingsCard`/`finCalculatorCard`، 20)، حساب‌ها و اشخاص صندوق (11)، لینک افتتاحیه |
| `assets` | تنظیمات اموال (`amSettingsView`، 12) |

`saveSettings()/saveLists()` HR همهٔ `[id^=set_]`/`[id^=list_]` سند را می‌خوانند؛ بنابراین هر گروه id فقط در یک بخش هاب ظاهر می‌شود و بلوک محل‌های وجه از کارت فهرست‌ها برداشته و در بخش خرید نمایش داده می‌شود. تب «تنظیمات» صفحه‌های تأمین (`suppliers.html?tab=json`)، مالی (`finance.html?view=settings`) و «دسته‌بندی و تنظیمات» اموال و دکمهٔ «تنظیم نرخ‌ها» داشبورد اموال به بخش مربوط هاب می‌روند (مسیر مستقیم قدیمی هم هدایت می‌شود). نمای «تنظیمات پنل و امکانات» همان کارت‌های HR را با همان ذخیره نشان می‌دهد.

## ۳. مدیریت اطلاعات، Backup و بازنشانی

Backup عمومی همهٔ ۱۰ ماژول را می‌خواند و در شکست هرکدام متوقف می‌شود. «بارگذاری اولیهٔ Seed» فقط برای ماژول خالی یا واقعاً مفقود (HTTP 404) و با اقدام صریح مدیر است؛ دادهٔ موجود و HTTP 500 اجازهٔ Seed نمی‌دهند. Load عادی هیچ Seed/Save خودکار ندارد.

بازنشانی جداول برای **شروع رستوران جدید در محیط دادهٔ مستقل** است، نه حذف موردی سوابق رستوران فعال:

- **خالی می‌شود**: همهٔ آرایه‌های رکورد (پرسنل و دسترسی، شیفت، حقوق، کالا، منو، رسپی و نسخه‌ها، تأمین، خرید، پرداخت، انبار، صندوق، فروش، مالی، اموال، نظرسنجی، ممیزی، لاگ) و دادهٔ عملیاتی تو‌در‌تو (تحلیل فروش، پیام روز شیفت، پیش‌نویس حقوق).
- **حفظ می‌شود**: ساختار سند، meta، تنظیمات، فهرست‌ها، مدل حقوق، نقشه و تعریف محل‌های انبار (برای اعتبار FK تنظیمات). شناسهٔ رکورد حفظ‌شده بازنویسی نمی‌شود. نام رستوران، نرخ‌ها، فهرست‌ها و حساب‌ها برای رستوران جدید باید بازبینی شوند.

مراحل: (۱) محیط داده/API مستقل (`js/app-config.js`؛ API پارامتر tenant ندارد و کپی HTML محیط را جدا نمی‌کند)، (۲) توقف ذخیرهٔ کاربران دیگر، (۳) «پیش‌نمایش بازنشانی جداول» فقط GET، (۴) بازخوانی و رد تغییر نسبت به پیش‌نمایش، دانلود اجباری Backup کامل JSON و عبارت `RESET TABLES`، (۵) Save فقط ماژول‌های تغییرکرده با مقایسهٔ محتوای بازخوانی‌شده، (۶) در شکست جزئی تلاش بازگردانی همهٔ ماژول‌های ارسال‌شده و نمایش بخش‌های ناموفق، (۷) بازگردانی با «پیش‌نمایش بازگشت آخرین عملیات» یا فایل JSON همان عملیات، Backup وضعیت فعلی و عبارت `RESTORE DATA`. فایل ZIP Backup عمومی با JSON بازنشانی یکی نیست. Save چندماژولی تراکنش اتمی سروری ندارد. فایل Backup را خارج از Git نگه دارید.
