# جداسازی تنظیمات و بازنشانی جداول

## تغییر رفتار

- صفحهٔ `settings.html` میزبان مدیریت اطلاعات و بکاپ، تنظیمات پنل، تنظیمات تخلفات، تغییرات و لاگ خطاها است. کاتالوگ همچنان در `base-data.html` باقی می‌ماند.
- لینک‌های قدیمی `personnel.html?view=...` برای این پنج نمای تنظیمات به مسیر جدید هدایت می‌شوند. تب‌ها و Back/Forward مسیر مستقل را حفظ می‌کنند؛ رفتن از تنظیمات به تقویم یا گزارش پرسنل به صفحهٔ پرسنل منتقل می‌شود.
- تنظیمات عمومی همچنان از سند `hr` / `personnel` خوانده و در همان سند ذخیره می‌شوند. منبع دادهٔ جدید یا نسخهٔ دوم تنظیمات ساخته نشده است.
- بازنشانی از Seed حذف شده است. بازنشانی جدید همهٔ ده ماژول را با هم پیش‌نمایش می‌کند و رکوردهای جداول را خالی می‌کند. این عملیات برای شروع یک رستوران جدید در محیط مستقل است، نه حذف موردی سوابق رستوران در حال کار.

## محدودهٔ بازنشانی

آرایه‌های رکورد، از جمله پرسنل و دسترسی پرسنلی، شیفت، حقوق، کالا، منو، رسپی و نسخه‌های آن، تأمین‌کنندگان، خرید، پرداخت، انبار، صندوق، فروش، مالی، اموال، نظرسنجی، ممیزی و لاگ، خالی می‌شوند. داده‌های عملیاتی تو‌در‌تو، مانند تحلیل فروش و پیام‌های روز شیفت، نیز پاک می‌شوند. پیش‌نویس محاسبهٔ حقوق و ارجاع‌های ممیزی به منوی قبلی پاک می‌شوند.

ساختار سند، متادیتا، تنظیمات، فهرست‌های انتخابی، مدل حقوق، نقشه و تعریف محل‌های انبار حفظ می‌شوند. نگهداری محل‌ها، ارجاع تنظیمات انبار به شناسهٔ محل را معتبر نگه می‌دارد. شناسه یا کد رکورد حفظ‌شده بازنویسی نمی‌شود. پیش‌نمایش تعداد قبل و بعد فهرست‌های حفظ‌شده را هم نشان می‌دهد.

نام رستوران، نرخ‌ها، فهرست‌ها و حساب‌های پرداختی که داخل تنظیمات تعریف شده‌اند باید برای رستوران جدید بازبینی شوند. این عملیات یک ابزار حذف کامل اطلاعات شناسایی یا انتقال چندمستاجری نیست.

## اجرا و بازگردانی

1. محیط داده/API رستوران جدید را مستقل آماده کنید. دامنهٔ API از `js/app-config.js` می‌آید و API فعلی برای انتخاب رستوران، پارامتر tenant ندارد؛ کپی HTML به‌تنهایی محیط داده را جدا نمی‌کند.
2. هنگام بازنشانی، سایر کاربران و صفحه‌های باز آن محیط نباید داده‌ای ذخیره کنند.
3. در «مدیریت اطلاعات و بکاپ»، «پیش‌نمایش بازنشانی جداول» را بزنید. این مرحله فقط GET دارد؛ شکست هر ماژول، عملیات را متوقف می‌کند.
4. پیش‌نمایش را بررسی کنید. دکمهٔ خالی‌کردن جداول، داده را دوباره می‌خواند و تغییر نسبت به پیش‌نمایش را رد می‌کند. پیش از اولین Save، بکاپ کامل JSON دانلود می‌شود. بعد از نگهداری فایل، عبارت `RESET TABLES` لازم است. داده پس از تأیید نیز دوباره کنترل می‌شود.
5. ذخیره فقط برای ماژول‌های تغییرکرده انجام می‌شود. علاوه بر بررسی توکن Save، محتوای بازخوانی‌شده با نتیجهٔ پیش‌نمایش مقایسه می‌شود.
6. در شکست جزئی، بازگردانی تمام ماژول‌های ارسال‌شده، شامل ماژولی که شاید ذخیره شده ولی تأیید نشده، تلاش می‌شود. شکست بازگردانی پنهان نمی‌شود؛ نام بخش‌های ناموفق و مسیر بازیابی نمایش داده می‌شود.
7. برای بازگردانی، از «پیش‌نمایش بازگشت آخرین عملیات» در همان نشست یا انتخاب فایل JSON دانلودشده در نشست جدید استفاده کنید. بعد از پیش‌نمایش، بکاپ وضعیت فعلی و عبارت `RESTORE DATA`، بازگردانی اجرا می‌شود. فایل ZIP بکاپ عمومی از فایل JSON مخصوص بازنشانی جدا است.
8. پس از پایان عملیات، صفحه را تازه کنید. فایل بکاپ را خارج از Git نگه دارید.

API قدیمی Save تراکنش مشترک بین ماژول‌ها ندارد. پیش‌بررسی و بازگردانی جبرانی جای تراکنش اتمی سمت سرور را نمی‌گیرد؛ اجرای هم‌زمان کاربران باید متوقف باشد.

بارگذاری اولیهٔ Seed یک گزینهٔ جدا و صریح برای ماژول خالی یا واقعاً مفقود (HTTP 404) باقی مانده است. دادهٔ موجود و خطای HTTP 500 اجازهٔ Seed نمی‌دهند. بارگذاری عادی صفحه هیچ بازنشانی، Seed یا Save خودکار جدیدی ندارد.

## اثر فنی و انتشار

- JSON: قرارداد و نام ماژول‌ها ثابت است؛ فقط اجرای دستی بازنشانی محتوای رکوردها را خالی می‌کند. ساختار بکاپ یک فایل قابل دانلود است و به DTO ماژول‌ها اضافه نمی‌شود.
- Backend/DTO: تغییری ندارد؛ همان Load/Save موجود استفاده می‌شود. فایل Backend مرجع، JSON را به‌صورت `JToken` می‌پذیرد.
- Migration: ندارد. نصب فایل‌های جدید هیچ داده‌ای را تغییر نمی‌دهد.
- Rollback کد: بازگرداندن commit؛ Rollback داده: فایل JSON پیش از عملیات طبق مراحل بالا.
- نسخهٔ محصول تغییر نکرده؛ `settings_split=1` فقط برای تازه‌شدن کش فایل‌های اصلاح‌شده در ارجاع‌های HTML است.
- هیچ دادهٔ واقعی در این توسعه خوانده، بازنشانی یا ذخیره نشده است.

فایل‌های اصلی: `settings.html`، `js/16-mpa-shell.js`، `js/17-v9-3-admin-enhancements.js`، `js/39-manual-initial-data-v10-8.js` و `js/44-phase1-polish-v10-10-1.js`. تغییرهای محدود `00`، `19`، `23`، `28` و `37` برای Load تنظیمات، نصب کنترل‌های فعلی و مسیرهای سازگار است. تغییر سایر HTMLها فقط ارجاع کش اسکریپت‌های اصلاح‌شده است. فایل patch تازه، CSS تازه یا ZIP انتشار ساخته نشده است.
