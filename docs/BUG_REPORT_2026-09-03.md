## ۳. جزئیات و مراحل بازتولید

### BUG-QA-001 — harness تست مغایرت صندوق اجرا نمی‌شود

**شرح:** فایل `qa_cash_variance.js` بخشی از `js/config.js` را از ابتدای تابع `cashAmount` تا پیش از `window.RAYO_API_GATEWAY` جدا و در VM اجرا می‌کند. برش فعلی، `})();` متعلق به IIFE فایل اصلی را نیز وارد قطعه می‌کند؛ در نتیجه قطعه مستقل یک آکولاد بسته اضافه دارد و قبل از اجرای assertionها با SyntaxError متوقف می‌شود.

**اثر:** منطق محاسبه کسری/اضافه صندوق توسط این QA قابل اعتبارسنجی نیست. این خطا به‌تنهایی ثابت نمی‌کند محاسبه محصول خراب است؛ فقط پوشش رگرسیون آن را از کار می‌اندازد.

**پیش‌شرط:** Node.js نصب باشد و ترمینال در ریشه پروژه باز شود.

**مراحل بازتولید:**

1. اجرا کنید: `node qa_cash_variance.js`
2. خروجی را مشاهده کنید.

**نتیجه فعلی:** اجرای VM با `SyntaxError: Unexpected token '}'` متوقف می‌شود و هیچ‌یک از تست‌های محاسباتی کامل نمی‌شوند.

**نتیجه موردانتظار:** فایل باید بدون خطای parser اجرا شود و سناریوهای تراز، اضافه صندوق، کسری صندوق، ارقام فارسی، ریال/تومان و اختلاف تاریخی را گزارش کند.

**علت ریشه‌ای محتمل:** تعیین انتهای قطعه با `config.indexOf('\n\nwindow.RAYO_API_GATEWAY', start)` مرز IIFE را نادیده می‌گیرد.

**پیشنهاد اصلاح:** منطق محاسبه به تابع/ماژول مستقل قابل import منتقل شود، یا harness انتهای دقیق export مربوط به `RayoCashVariance` را جدا کند. پس از اصلاح، تست باید با exit code صفر اجرا شود.

### BUG-QA-002 — QA v10.12.0 پیاده‌سازی صحیح reorder را اشتباه Fail می‌کند

**شرح:** تست فقط وجود literalهای `reorderPoint` و `targetStock` را در فایل inventory بررسی می‌کند. در سورس فعلی، محاسبه نقطه سفارش به helper مشترک `RayoReorder.assess` منتقل شده است؛ بنابراین `reorderPoint` الزاماً در فایل `46` ظاهر نمی‌شود، با وجود اینکه UI و منطق سفارش مجدد برقرار است.

**اثر:** pipeline یا بررسی دستی نسخه با یک Fail کاذب متوقف می‌شود و وضعیت انتشار را اشتباه قرمز نشان می‌دهد.

**مراحل بازتولید:**

1. اجرا کنید: `node qa_v10_12_0.js`
2. خروجی نهایی را بررسی کنید.

**نتیجه فعلی:** `RESULT 25/26 PASS` و `FAIL reorder list` با exit code برابر ۱.

**شاهد مقابل:** `node qa_reorder_point.js` تمام **۲۲/۲۲** کنترل رفتاری نقطه سفارش، مقدار صفر، واحد، fallback legacy، rollback و موجودی فیزیکی را پاس می‌کند.

**نتیجه موردانتظار:** QA نسخه‌ای باید قرارداد رفتاری/helper مشترک را بررسی کند و با پیاده‌سازی فعلی PASS شود.

**پیشنهاد اصلاح:** assertion متنی با تست رفتاری `RayoReorder.assess` و بررسی خروجی جدول جایگزین شود.

### BUG-QA-003 — QA v10.11.0 مقدار cache-bust منسوخ را انتظار دارد

**شرح:** تست انتظار دارد loader فایل `44-phase1-polish-v10-10-1.js` با query نسخه `10.11.0` باشد، درحالی‌که loader فعلی عمداً به `10.12.1` ارتقا یافته است.

**مراحل بازتولید:**

1. اجرا کنید: `node qa_v10_11_0.js`
2. شکست `FAIL: v10.11 cache bust` را مشاهده کنید.

**نتیجه موردانتظار:** تست نسخه قدیمی نباید مقدار cache-bust انتشار جدید را Fail تلقی کند؛ یا باید فقط در artifact همان نسخه اجرا شود، یا نسخه موردانتظار از manifest/build marker خوانده شود.

**پیشنهاد اصلاح:** QAهای نسخه‌ای را immutable و وابسته به artifact همان نسخه نگه دارید؛ برای شاخه `main` یک QA تجمیعی جاری بسازید.

### BUG-QA-004 — QA v10.10.1 متن قدیمی Audit را جست‌وجو می‌کند

**شرح:** تست literal عبارت `Audit سپیدز` را داخل فایل polish قدیمی جست‌وجو می‌کند. ناوبری جاری به صفحات مستقل فروش و ممیزی منتقل شده و QA جدید `qa_sales_audit_navigation.js` قرارداد فعلی را بررسی می‌کند.

**مراحل بازتولید:**

1. اجرا کنید: `node qa_v10_10_1.js`
2. شکست `FAIL: sales audit tab` را مشاهده کنید.

**شاهد مقابل:** `node qa_sales_audit_navigation.js` تمام **۱۲/۱۲** کنترل مسیر فروش/ممیزی، active tab، ثبت route و دسترسی مستقیم را پاس می‌کند.

**نتیجه موردانتظار:** تست قدیمی روی main اجرا نشود یا assertion آن به قرارداد ناوبری فعلی ارتقا یابد.

### BUG-DOC-001 — README با نسخه عملیاتی همخوان نیست

**شرح:** سند مرجع و AGENTS baseline را v10.12.1 اعلام می‌کنند، اما عنوان README هنوز `Rayo Admin v10.10.0` است و فرمان `node qa_v10_10_0.js` و اسناد v10.10.0 را به‌عنوان مسیر اصلی معرفی می‌کند.

**اثر:** توسعه‌دهنده یا اپراتور جدید ممکن است QA ناقص/قدیمی اجرا کند، نسخه اشتباه را مبنا بگیرد یا مستندات جدید را نبیند.

**مراحل بازتولید:**

1. فایل `README.md` را باز کنید.
2. خط اول و بخش‌های «QA» و «مستندات مرجع» را با `docs/RAYO_ADMIN_MASTER_HANDOFF_v10_12_1.md` مقایسه کنید.

**نتیجه فعلی:** README نسخه 10.10.0 را نمایش می‌دهد.

**نتیجه موردانتظار:** README باید baseline رسمی v10.12.1، QA جاری و سند master handoff را معرفی کند.

## ۴. ریسک‌های محصول که باید در Backlog باقی بمانند

### RISK-001 — Lost Update در ویرایش هم‌زمان

**شدت:** بحرانی در استفاده چندکاربره  
**وضعیت:** محدودیت معماری شناخته‌شده؛ در این بررسی به Backend زنده دسترسی نبود تا وقوع آن end-to-end تأیید شود.

**سناریوی بازتولید پیشنهادی در Stage:**

1. دو مرورگر/کاربر A و B یک module یکسان را Load کنند.
2. A رکورد اول و B رکورد دوم را تغییر دهند.
3. A ذخیره کند و سپس B با نسخه قدیمی همان سند کامل ذخیره کند.
4. module دوباره Load و تغییر A بررسی شود.

**نتیجه ناخواسته محتمل:** در نبود کنترل version/ETag سمت Backend، ذخیره B تغییر A را بازنویسی می‌کند.

**معیار پذیرش:** درخواست دوم با conflict صریح (مانند HTTP 409) رد شود، UI read-only/refresh شود و هیچ retry خودکار برای conflict رخ ندهد.

### RISK-002 — Feature Visibility کنترل دسترسی نیست

**شدت:** زیاد در محیط دارای نقش‌های متفاوت  
**وضعیت:** محدودیت شناخته‌شده.

**سناریوی بازتولید پیشنهادی در Stage:**

1. یک قابلیت را از تنظیمات نمایش برای یک کاربر مخفی کنید.
2. URL مستقیم همان صفحه یا endpoint مربوط را باز کنید.
3. امکان مشاهده/عملیات را بررسی کنید.

**نتیجه ناخواسته محتمل:** مخفی شدن فقط در UI است و مانع دسترسی مستقیم نمی‌شود.

**معیار پذیرش:** مجوزها در Backend برای هر Query/Mutation اعمال و درخواست فاقد نقش با 403 رد شود.
